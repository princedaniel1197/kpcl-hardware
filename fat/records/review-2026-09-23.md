The review asked for one thing above all: that every claim the FAT makes be one
the system could fail. The records below say, for each finding, what was wrong,
what changed, and what was **measured** afterwards. Where a stage record states
something this review showed to be wrong, that record carries a dated
correction pointing here; the original text is left in place, because a record
that silently changes is worth less than one that shows its corrections.

## A — fix before anyone sees it

### A1. Relay polarity — and three firmware defects behind it

The relay modules are active-low; the firmware drove them active-high. At boot
both relays would have energised, every fan started, and the ACS712 zeroed with
~0.46 A flowing; every ON command then switched a relay OFF.

Fixed: `RELAY_ACTIVE_LOW` in `firmware/src/rig_config.h`; the de-energised level
is written before the pins become outputs (a bench check confirms no relay clicks at reset, and `RELAY_OPEN_DRAIN` covers a module a 3.3 V HIGH will not release); the current sensor is zeroed only
with both relays open and settled for 300 ms, the zero is checked for
plausibility (2300–2700 mV), exposed in input register 7, and can be redone
through coil 2 — refused while a relay is on. CLAUDE.md's hardware table now
says "active-low".

Found while fixing it:

- **The DS18B20 probes were assigned by bus search order.** Search order follows
  the ROM codes, not the physical probes, so "hub" and "ambient" were a coin
  toss — and with the hub probe unplugged at boot, the ambient probe was found
  first and **published as the hub temperature**. That is the Stage 10 test
  condition itself producing a silently substituted sensor. Probes are now read
  by configured ROM address; until configured, both report invalid and the
  bridge publishes `BadConfigurationError`.
- **Every temperature from 84.9 °C up was rejected as the power-on-reset
  value**, which would have turned an overheating motor into a failed sensor.
  Only exactly 85.0 is rejected now.
- **The supply status bit meant "10.5–13.5 V"**, so a brown-out reading became
  BadDeviceFailure with no value. It now means "the ADC could measure it"; a
  low supply is a measurement, and judging it is the quality engine's job.
- Current and vibration reported **0** on a failed read, which is what a
  stopped fan reads. Every channel now has a sentinel. Current is a signed
  **mean**, not an RMS, so a wrong zero shows as an impossible negative current.
- **The firmware had never been compiled, and could not have been:** its eModbus
  dependency named a package that does not exist in the PlatformIO registry
  (`eModbus/eModbus`; it is `miq19/eModbus`).

Measured: both builds compile cleanly with `-Wall -Wextra` (PlatformIO 6.2.0,
espressif32 7.1.3, versions pinned): TCP 807,117 bytes flash (61.6 %), 44,452
bytes RAM (13.6 %); RTU 340,841 bytes flash (26.0 %), 22,536 bytes RAM (6.9 %).
**Not flashed, not run on hardware.** The register map is now version 2
(`firmware/REGISTER_MAP.md`, with a table of every change). The end-to-end test
through the stand-in — register image over real Modbus TCP, bridge, real OPC UA
server, real client — passes: hub unplugged gives `BadDeviceFailure` with a null
value on `RIG_HUB_TEMP` and nothing else.

### A2. The SLDC recorder discarded per-unit generation

Fixed first, because it lost data every minute. From **02:47 UTC on 23
September** all 33 units are recorded in `sldc_unit_generation`, keyed
`(station, unit, source_ts)`, through the same Bad-with-reason path as the
totals; the schema refuses a Bad row with a number. `sldc_unit_consistency`
compares each station total with its unit sum per page timestamp and says
`consistent`, `inconsistent`, or `incomplete` when any input is not Good — a
Bad unit is never counted as 0 MW. Tolerance is per-station configuration.

Measured: on the captured fixture **RTPS published 1190 MW with all eight units
at 0 MW**, and the check flags it. On the live feed since 02:47, 60 of 60
station readings consistent; largest unit-sum difference 13 MW (YTPS). Units
before 02:47 are not recoverable.

### A3. The API had no authentication

Every route now takes a principal from a bearer token through
`ops.access.authenticate`; what each route needs is one table in `api/auth.py`,
and a route not in it is refused. The station role is scoped on every route that
returns station data, and data mapped to no station is refused to it (scope
fails closed). The WebSocket takes the token as a subprotocol, never in the URL.
CORS is limited to the UI's origins and GET; the schema pages are off unless
asked for. The UI signs in with a token held in `sessionStorage`.

Measured: `api/test_auth.py`, 29 tests against a real server and against the
running API: no token → 401 on all ten routes; unknown token → 401; admin → 200
on all ten; a BTPS token reading RTPS data → 403, and every list endpoint returns
nothing to it; an RTPS token reading a tag mapped to no station → 403; an
undeclared route and a missing permission → 403; WebSocket refused without a
token and accepted with one. Through the Vite proxy: 401 without a token, 200
and a working WebSocket with one. T-18 now runs this against the live API.

### A4. The collector could fabricate identical timestamps

`sample.server_ts` is nullable (migration 014) and a missing ServerTimestamp is
stored as NULL — never source_ts, never receipt time — in the collector, the OMF
emitter (explicit `null`) and the OMF receiver (which now refuses an omitted
ServerTime or Quality rather than defaulting them). The collector's own health
samples carry no server_ts: no server put them on a wire. Counted as
`NO_SERVER_TS`. T-07 counts unstamped rows separately rather than as a pass.

## B — claims the code did not back

### B1. Gap detection could not detect anything

Replaced by two real mechanisms. **Source to collector:** the server's
NotificationMessage SequenceNumber, keep-alives included (Part 4), checked per
subscription; `test_session.py` drops one real PublishResponse against a real
server and the count is exactly 1. **Collector to archive:** every collector
start is a `collector_run`; every sample the run decides to archive is numbered
per tag, and run and number are stored with the row; `sample_seq_gap` lists
every hole with what explains it (another run's rows, or `collector_loss`).
Buffer overflow is written to `collector_loss` in the same transaction as the
discard. `buffer.py` and `config.py` no longer claim what was not true.

Limit, stated: a hole needs neighbours. A missing sample before a run's first
archived row or after its last is not visible by sequence alone.

### B2. Compression was not in the live path

It is now, per tag (`tag.compress`), off by default so that the zero-loss claim
stays a claim about every sample. The README and the FAT say so where they say
"passed". `python -m collector` flushes each compressor's open segment on a
clean stop.

Measured through the collector's own Pipeline against the simulator
(`make compression-report`, 120 s, steady load): **15 of 15 tags within
CompDev**, U1_MS_TEMP **34.4:1**, U1_BEARING_VIB **1.2:1**, 3,112 raw → 461
archived overall. T-10 now runs this.

### B3. T-12 could not fail

Re-criterioned on source CPU per subscribed tag, measured from the kernel's
per-process accounting at nanosecond resolution (`fat/proc_cpu.py`, checked
against `getrusage`: 0.99967 s vs 0.99967 s), and the source's own per-scan work
time, over alternating attached/detached windows. Budget, stated as ours: 0.5 %
of one core per subscribed tag; scan work P95 within 10 % or 1 ms.

Shown able to fail (`make intrusion-demo`): a read-only client polling the 14
Unit 1 tags at 32,640 reads/s costs the source **3.37 % of one core per tag** —
6.7 × the budget — and fails. Recorded honestly beside it: under that load the
scan work time *fell* (2.13 → 0.65 ms P95), because the laptop's CPU clocked up;
on this hardware scan time does not discriminate, CPU does.

### B4. T-04 passed at 99.9 % loss

T-04 now looks up every sample the simulator published — its own ledger of the
writes a subscription must report (`sim/ledger.py`), with the rule for which
writes those are measured against asyncua, not assumed — in the archive by exact
source timestamp. Measured on a 6-minute window: **7,946 of 7,946**. Minute
coverage is reported beside it.

### B5. Missing quality was stored as Good

Refused and counted (`DROP_NO_STATUS`).

### B6. Dropped samples were only logged

`DROP_NO_SOURCE_TS`, `DROP_NO_STATUS`, `DROP_UNSTORABLE`, `NO_SERVER_TS`,
`DUPLICATE_TS`, `PUBLISH_MISSED`, `BUFFER_LOST` and `TAGS_UNRESOLVED` are health
tags, per instance, generated from `collector/health.py` so tags and code cannot
drift. A string or array value is now refused and counted, not stored empty
beside a Good code.

### B7. Source deadband was off globally

Per server now (`config/sources.json`, matched on the server's ApplicationUri so
typing the address differently cannot change it), on by default, off for the
simulator. Measured (`make deadband-evidence`, 30 s, 14 tags): deadband on
**6.8 notifications/s and 0 Bad notifications** when U1_MS_PRESS was forced to
BadDeviceFailure; off, **22.0/s and the Bad notification arrived**. A test pins
the asyncua defect so a fixed asyncua fails it.

### B8. 1,251 range flags on a simulator inside its spans

Neither the EURanges nor the plant model: they were the **Stage 6 demonstration
narrowing U1_MS_TEMP's EURange to 0–300 °C** to force the out-of-range
condition, with a direct UPDATE and **no audit row**, so nothing explained them.
That is a §433 defect in its own right. Configuration is now changed through
`archive/audit.py` — old value read in the same transaction, no row for a
non-change — and the demonstration restores in a `finally`. Two of its checks
tested a constant's severity instead of the flag produced; they now test the
flag. T-05 now forces all four conditions and counts only its own flags.

## D — tests that could not fail

Every automated test in `fat/plan.py` now states what would make it fail, and
the ITP and the report print it. The three named tests have real criteria
(above). T-05 forces all four conditions; T-10 measures the live path; T-13
drives the handler instead of grepping its source; T-18–T-20 run against the
live system instead of pointing at the unit suite.
